# BeerVia ML: распознавание этикетки по фото

Отдельный Python-сервис рядом с `server/` (Node) и `mobile/` (Expo).

## Как это работает

Распознавание идёт в два этапа, и ручной сбор фото для запуска не обязателен.

1. **По эталонным фото.** Нейросеть **CLIP** превращает фото в вектор (набор чисел): похожие картинки
   дают близкие векторы. Если для пива есть эталонные фото в `dataset/`, новая фотография сравнивается
   с ними. Это самый точный способ.
2. **По названию.** Если эталонных фото нет (или фото не совпало), CLIP сопоставляет снимок с текстом
   «банка такой-то пивоварни такое-то пиво»: он умеет читать крупные надписи и знает многие бренды.
   Для этого не нужно ни одного фото, только название из каталога. Точность ниже, чем по фото,
   поэтому уверенным ответом считается только явный лидер, а при сомнениях приложение показывает
   «Возможно, это…».

Итог для пользователя:
- уверенно узнали, пиво открывается;
- сомневаемся, приложение показывает варианты;
- не узнали ни по фото, ни по названию, приложение честно говорит об этом и предлагает найти пиво
  вручную, добавить его или отсканировать штрихкод.

Чем больше эталонных фото, тем лучше. Их можно докачивать автоматически из открытой базы
(`fetch_off_photos.py`) и добавлять свои. Новое пиво добавляется без переобучения: запустили
`build_gallery.py` (секунды), и оно узнаётся.

Файлы:

| Файл | Зачем |
|---|---|
| `server: npm run export-labels:local` | выгрузить весь каталог пива в `dataset/labels.json` |
| `fetch_off_photos.py` | скачать фото упаковок из открытой базы Open Food Facts в `dataset/` |
| `build_gallery.py` | собрать галерею (`gallery.npz`, `gallery.json`) и подобрать пороги |
| `evaluate.py` | проверить качество на фото, которых в галерее нет |
| `serve.py` | сервис `/recognize`, к нему обращается `server/` |

## Настоящий каталог и «студийные» картинки

Каталог пива берётся из открытой базы Open Food Facts: самое популярное в России и в мире, с
названиями, пивоварнями, штрихкодами и фото упаковки. Из фото делается «студийная» картинка (банка
без фона, по центру), которая показывается после скана и в карточке пива.

**Один раз** (сервер остановите, `Ctrl+C`; старая тестовая база с придуманными сортами будет удалена
вместе с тестовыми аккаунтами):

```
cd /d/beervia-app/server
rm prisma/dev.db
npm run import-beers:local -- --dry-run          # посмотреть, что найдётся, ничего не записывая
npm run import-beers:local -- --country=russia --limit=300 --world=100
cd ../ml
pip install -r requirements-cutout.txt            # один раз: нейросеть для вырезки (скачает модель, нужен VPN)
python import_inbox.py --cut                      # свои фото из ml/inbox: разложить по сортам и вырезать фон
python build_gallery.py                           # собрать галерею для распознавания
cd ../server
npm run sync-photos:local                         # подставить картинки в каталог
npm run dev:local
```

Что важно знать:
- Вкус (сладость, горечь и т. д.) у импортированных сортов оценивается по типичному для стиля, а не
  по данным о конкретном пиве: таких данных в открытых базах нет.
- В Open Food Facts нет фото или самого пива для части сортов. Для таких сортов приложение
  показывает заглушку, пока картинку не добавят.
- `make_cutouts.py` сам выбирает лучший способ: нейросеть BiRefNet (после
  `pip install -r requirements-cutout.txt`), иначе `rembg`, иначе вырезка только на однородном фоне.
  Нейросеть вырезает любой фон и убирает тень; на процессоре это 10–30 секунд на фото, первый запуск
  скачивает модель. Если вырезка не получилась чисто, остаётся целое фото упаковки, а не обрубок.
  `--preview` сохраняет `cutout-preview.jpg`: оригиналы слева, вырезки на цветном фоне справа.
  Если фото из Open Food Facts плохое (полка магазина, задняя этикетка, рядом другой предмет), положите
  своё в папку сорта под именем `front.jpg` (`ml/dataset/<папка сорта>/`) и запустите
  `python make_cutouts.py --force --only <папка сорта>`: своё фото берётся первым.
  Много своих фото удобнее разложить скриптом: положите их в `ml/inbox/`, назвав по пиву («Балтика 7.jpg»,
  «Hoegaarden Белое.jpg»), и выполните `python import_inbox.py`. Он сам найдёт сорт в каталоге; что не
  распознал, оставит в `inbox/` и назовёт в отчёте. С флагом `--cut` фон вырезается сразу.
- В приложении показываются только ваши картинки: вырезка `cutout.png`, сделанная из вашего фото `front.*`.
  Фото Open Food Facts нужны только для распознавания, в приложении их нет. Чтобы начать с чистого листа:
  `npm run clear-photos:local` в папке `server` (убирает картинки из приложения и удаляет вырезки;
  `-- --originals` удаляет ещё и скачанные фото Open Food Facts, `-- --front` ещё и ваши фото).
- Запускать импорт повторно безопасно: то, что уже есть, пропускается. Для другой страны:
  `--country=belarus` или несколько через запятую.

## Установка (Windows)

1. Установите Python 3.11 или новее с python.org. На первом экране установщика поставьте галочку
   **Add python.exe to PATH**. Проверка: `python --version`.
2. В Git Bash:
   ```
   cd /d/beervia-app/ml
   python -m venv venv
   source venv/Scripts/activate
   pip install -r requirements.txt
   ```
   Скачивается PyTorch, это несколько сотен мегабайт, ждать 5–10 минут. Признак активной среды:
   в начале строки `(venv)`. Каждый раз в новом окне сначала `source venv/Scripts/activate`.

## Шаг 1. Каталог и фото (можно почти без ручной работы)

```
cd /d/beervia-app/server
npm run export-labels:local       # весь каталог пива -> ml/dataset/labels.json
cd ../ml
python fetch_off_photos.py        # фото упаковок из Open Food Facts
```

`fetch_off_photos.py` ищет каждое пиво в Open Food Facts и кладёт фото упаковки в `dataset/<марка>/`.
Это идёт неторопливо (сервис просит не больше 10 запросов в минуту), в конце скрипт покажет, для каких
марок фото не нашлось. Такие марки будут узнаваться по названию.

**Свои снимки телефоном повышают качество.** Фото из базы «студийные» (упаковка анфас), а пользователи
снимают под углом, при плохом свете. По 5–10 своих фото проблемных марок в их папки заметно улучшают
результат, но это можно делать позже, после первого запуска, ориентируясь на `evaluate.py`.

## Шаг 2. Собрать галерею и проверить качество

```
python build_gallery.py
python evaluate.py
```

Первый запуск скачивает веса CLIP (около 350 МБ), для этого может понадобиться VPN.

`evaluate.py` пишет отдельные блоки:
- **По эталонным фото**: как часто узнаёт новое фото знакомой марки (хорошо: 85% и выше) и верно ли,
  когда отвечает уверенно (хорошо: 95% и выше); отвергает ли незнакомое пиво (хорошо: 85% и выше).
- **Только по названию, без эталонных фото**: то же, но так, будто фото нет вообще. Это то качество,
  которое получают пива без снимков. Ориентир: верное пиво в первой тройке у 60–70% и выше уже
  полезно (приложение покажет варианты), а уверенных ответов должно быть верных 90% и выше.

Если по названию результат слабый, не страшно: добавляйте эталонные фото проблемных марок.

## Шаг 3. Запустить сервис

```
uvicorn serve:app --host 0.0.0.0 --port 8001
```

Проверка: `http://localhost:8001/health` должен показать `"modelLoaded": true`.

В `server/.env` укажите (и перезапустите сервер):
```
ML_SERVICE_URL="http://localhost:8001"
```

Дальше в приложении фото этикетки сначала сверяется с галереей.

## Как добавить новое пиво

1. Добавьте его в каталог (в приложении или через сервер), затем `npm run export-labels:local` в папке `server`.
2. `python fetch_off_photos.py` (или положите свои фото в `dataset/папка/`).
3. `python build_gallery.py`, затем перезапустите `serve.py`.

Даже без фото шаги 1 и 3 уже дают распознавание по названию.

## Настройки

- Порог «узнали» подбирается автоматически при сборке галереи и записывается в `gallery.json`.
  Свой порог: переменная `BEERVIA_ML_THRESHOLD` (например `0.85`) при запуске `serve.py`.
- Меньше ложных «узнал»: поднимите порог. Чаще предлагает варианты: опустите.

## Сколько это стоит на сервере

CLIP ViT-B/32 работает и на обычном процессоре: доли секунды на фото, нужно около 1–2 ГБ памяти.
Отдельная видеокарта не требуется.

## Проверка кода без нейросети

`pytest tests` прогоняет весь конвейер на искусственных «этикетках» со встроенным упрощённым
эмбеддером (без скачивания моделей). Это проверка логики, а не качества на настоящих банках.
