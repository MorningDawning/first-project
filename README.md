# BeerVia 🍺

Мобильное приложение — аналог Vivino, но для пива. Сканируешь банку/этикетку
— получаешь карточку пива с сортом, маркой, отзывами, вкусовым профилем,
процентом совпадения со своим вкусом и рекомендациями по еде.

## Структура репозитория

```
server/   — backend: Node.js + TypeScript + Express + Prisma (SQLite)
mobile/   — фронтенд: React Native (Expo) + TypeScript
ml/       — распознавание этикетки: дообучение CLIP (linear probe) + FastAPI-сервис
```

## Возможности

- **Главная** — приветствие, рекомендации по вкусу, кнопка «Сканировать»,
  открывающая камеру отдельным экраном.
- **Сканер** — снимок этикетки отправляется на ML-сервис распознавания
  (дообученный CLIP, см. `ml/`); пока чекпоинт не обучен на реальных фото —
  честно уходит в резервный сценарий, а не притворяется рабочим.
- **Библиотека** — поиск и фильтрация пива по названию, пивоварне, стилю.
- **Бар** — история всего, что пользователь отсканировал.
- **Профиль** — карточка пользователя, вкусовой профиль (по отзывам и
  сканированиям), библиотека пивоварен мира, настройки, лента друзей
  (текстовые посты с фото).
- Карточка пива: сорт/марка/пивоварня, отзывы и рейтинг, **процент
  совпадения со вкусом пользователя**, вкусовой профиль (радар-диаграмма),
  с какой едой сочетается, похожие сорта («рекомендации»).

## Backend (`server/`)

Node.js + Express + Prisma. База данных — SQLite (файл `server/prisma/dev.db`),
чтобы не требовать отдельного сервера БД; в проде легко переключить `DATABASE_URL`
на PostgreSQL — схема Prisma останется той же.

```bash
cd server
npm install
npx prisma migrate dev   # создаёт БД и применяет схему
npm run seed              # заполняет демо-данными (пиво, пивоварни, отзывы)
npm run dev                # запускает API на http://localhost:4000
```

Демо-аккаунт: `demo@beervia.app` / `demo1234`.

### Основные эндпоинты

- `POST /auth/register`, `POST /auth/login`
- `GET/PATCH /me`
- `GET /beers?q=&style=`, `GET /beers/:id`, `POST /beers/:id/reviews`
- `POST /scan` — принимает фото (`multipart/form-data`, поле `photo`), зовёт ML-сервис
  распознавания; без уверенного результата — штрихкод или случайный выбор, создаёт запись в истории
- `GET /bar` — история сканирований пользователя
- `GET /breweries`, `GET /breweries/:id`
- `GET /taste-profile` — агрегированный вкусовой профиль пользователя
- `GET/POST /feed` — лента друзей

Все эндпоинты, кроме `/auth/*`, требуют заголовок `Authorization: Bearer <token>`.

## Mobile (`mobile/`)

React Native на Expo. В этой облачной песочнице нет телефона/симулятора для
визуальной проверки — проверено через `tsc --noEmit` (чисто) и
`expo export --platform android/ios` (бандл собирается без ошибок, ~1000
модулей). Реальный запуск на устройстве:

```bash
cd mobile
npm install
npm start          # откроется Expo Dev Tools / QR-код
```

Дальше — отсканировать QR-код приложением **Expo Go** на телефоне (в той же
Wi-Fi сети, что и компьютер с сервером), либо `npm run android` /
`npm run ios` при наличии эмулятора.

### Подключение к backend

Адрес backend определяется автоматически (`mobile/src/api/config.ts`): в Expo
Go приложение берёт LAN-адрес вашего компьютера из того же соединения, что и
QR-код, — вручную ничего указывать не нужно. Для Android-эмулятора
используется `10.0.2.2:4000`, для iOS-симулятора/веба — `localhost:4000`.
Backend должен быть запущен и слушать порт `4000` до того, как вы откроете
приложение.

## ML — распознавание этикетки (`ml/`)

Дообучение CLIP (linear probe — backbone заморожен, обучается только классификатор поверх
эмбеддингов) на собственном датасете фото банок/этикеток. Полная инструкция — `ml/README.md` и
протокол съёмки датасета — `ml/dataset/README.md`.

```bash
cd ml
python -m venv venv && source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
python train_clip.py --data dataset --out checkpoint.joblib   # после того как собраны фото
BEERVIA_ML_CHECKPOINT=checkpoint.joblib uvicorn serve:app --port 8001
```

Backend находит сервис через `ML_SERVICE_URL` в `server/.env` (по умолчанию `http://localhost:8001`).
Без обученного чекпоинта или без запущенного сервиса `/scan` просто уходит в резервный сценарий —
остальное приложение работает как обычно.

## Известные упрощения (что доделать для продакшена)

- **Сканирование** — распознавание подключено, но чекпоинт ML-модели ещё не обучен (датасет
  реальных фото пока не собран, см. `ml/dataset/README.md`) — до этого момента `/scan` работает в
  резервном режиме (штрихкод или случайный выбор).
- **Фото в постах ленты** — публикация принимает ссылку на изображение
  (URL), а не загрузку файла с телефона — нужно добавить загрузку в
  файловое хранилище (S3/Cloudinary и т.п.).
- **Видео в ленте друзей** — вынесено за рамки первого этапа по договорённости.
- **Лента друзей** — сейчас общая для всех пользователей; модель
  `Friendship` в схеме уже есть, фильтрацию по реальным друзьям можно
  добавить отдельным шагом.
- **База данных** — SQLite для простоты разработки; для продакшена
  переключить на PostgreSQL через `DATABASE_URL`.
