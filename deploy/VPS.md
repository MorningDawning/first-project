# Сервер BeerVia на российском хостинге (виртуальный сервер, VPS)

Вы арендуете один небольшой сервер у российского провайдера (оплата российской картой или СБП),
и на нём запускается всё сразу: API, база Postgres и автоматический HTTPS. Ваш компьютер после
этого для сервера не нужен, VPN на телефоне тоже.

> Файлы этого набора (`docker-compose.yml`, `Caddyfile`) проверены на корректность, а сам сервер
> проверен на Postgres. Целиком на настоящем VPS набор я не запускал, поэтому в конце есть раздел
> «Если что-то пошло не так».

## Шаг 0. Выбрать хостинг и заказать сервер

Подойдёт любой провайдер, у которого можно арендовать виртуальный сервер и платить российской
картой: например Timeweb Cloud, Selectel, Beget, REG.RU, VDSina. Заказывайте так:

- **Система (образ):** Ubuntu 24.04, чистая, без панелей (ISPmanager, Plesk и т. п.).
- **Размер:** 2 ГБ памяти, 1–2 ядра, диск от 20 ГБ. Ориентир по цене: несколько сотен рублей в
  месяц (уточните на сайте провайдера).
- **Расположение:** Россия (Москва или Санкт-Петербург).
- **Публичный IPv4-адрес:** обязательно, обычно входит в тариф.

После оплаты провайдер покажет (или пришлёт на почту) **IP-адрес** сервера и **пароль root**.
Запишите их.

## Шаг 1. Подключиться к серверу

На вашем компьютере откройте **PowerShell** (правой кнопкой по «Пуск» → «Терминал» или
«Windows PowerShell») и выполните, подставив свой IP:

```
ssh root@185.12.34.56
```

На вопрос `Are you sure you want to continue connecting` ответьте `yes`, затем введите пароль.
При вводе пароля символы не отображаются: это нормально. Когда появится приглашение вида
`root@...:~#`, вы внутри сервера. Дальше все команды выполняйте там.

## Шаг 2. Установить Docker и Git

```
apt update && apt install -y docker.io docker-compose-v2 git
```

Проверка: `docker compose version` должна показать версию.

## Шаг 3. Скачать код

```
git clone -b claude/app-development-og0ydh https://github.com/MorningDawning/first-project.git
cd first-project/deploy
```

Если репозиторий приватный, git спросит логин и пароль. Логин — ваше имя на GitHub. Вместо
пароля вставьте **токен**: GitHub → Settings → Developer settings → Personal access tokens →
Fine-grained tokens → создать, выбрать только репозиторий `first-project`, право **Contents:
Read-only**.

## Шаг 4. Настроить

```
cp .env.example .env
nano .env
```

В открывшемся редакторе заполните три строки:

- `DOMAIN` — бесплатное имя на основе IP-адреса: точки заменяются дефисами и добавляется
  `.sslip.io`. Для IP `185.12.34.56` получится `185-12-34-56.sslip.io`.
- `POSTGRES_PASSWORD` и `JWT_SECRET` — по длинной случайной строке. Получить каждую можно
  командой `openssl rand -hex 32` (выполните её в другом окне PowerShell на сервере или тут же
  после выхода из редактора, скопируйте результат).

Сохранить и выйти из nano: `Ctrl+O`, `Enter`, `Ctrl+X`.

## Шаг 5. Запустить

```
docker compose up -d --build
```

Первый запуск идёт 5–10 минут: собирается сервер и скачиваются образы. Затем проверьте:

```
docker compose ps
docker compose logs api --tail 30
```

В логах API должны быть строки «Каталог пива загружен ✅» и «BeerVia API listening».

Откройте в браузере `https://ВАШ-ДОМЕН/health` (например `https://185-12-34-56.sslip.io/health`).
Должно появиться `{"ok":true}`. Сертификат HTTPS выпускается автоматически, это может занять
минуту.

## Шаг 6. Подключить приложение

В `D:\beervia-app\mobile` создайте файл `.env` со строкой (ваш домен, без слэша в конце):

```
EXPO_PUBLIC_API_URL=https://185-12-34-56.sslip.io
```

Затем `npx expo start --clear`. Зарегистрируйтесь в приложении заново: база на сервере пустая,
там только каталог пива.

Чтобы у аккаунта появились вымышленные друзья, посты и переписка (для показа), на сервере в папке
`first-project/deploy` выполните после регистрации:

```
docker compose exec api npx tsx prisma/seedSocial.ts
```

Она только добавляет данные и ничего не стирает. Никогда не запускайте `prisma/seed.ts` на
боевой базе: он стирает всё.

## Как обновлять сервер

Когда в ветке появляется новая версия кода, на сервере выполните:

```
cd ~/first-project
git pull
cd deploy
docker compose up -d --build
```

Изменения в базе применяются автоматически при запуске. Сервер недоступен около минуты.

## Резервные копии

Данные пользователей лежат в базе на этом сервере. Включите автоматические снимки диска в панели
провайдера и, кроме того, время от времени делайте копию базы:

```
cd ~/first-project/deploy
docker compose exec -T db pg_dump -U beervia beervia > backup-$(date +%F).sql
```

## Безопасность (рекомендую сделать сразу)

Закройте лишние порты, оставив только вход по SSH и веб:

```
ufw allow OpenSSH
ufw allow 80
ufw allow 443
ufw enable
```

Порядок важен: сначала разрешить `OpenSSH`, потом включать `ufw`, иначе можно отрезать себя
от сервера. Пароль root после первого входа лучше сменить командой `passwd`.

## Если что-то пошло не так

- **Не скачиваются образы Docker** (ошибка `403 Forbidden`, `timeout` на `docker.io`). Docker Hub
  иногда недоступен из России. Подключите зеркало:
  ```
  mkdir -p /etc/docker
  echo '{"registry-mirrors":["https://mirror.gcr.io"]}' > /etc/docker/daemon.json
  systemctl restart docker
  ```
  и повторите `docker compose up -d --build`.
- **Сборка обрывается, в логах `Killed` или нехватка памяти.** Добавьте файл подкачки:
  ```
  fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
  ```
  и повторите запуск.
- **Страница `/health` не открывается или пишет про сертификат.** Проверьте, что в панели
  провайдера открыты порты 80 и 443, и посмотрите `docker compose logs caddy --tail 50`. Если
  сертификат для `sslip.io` не выдаётся, купите свой домен (около 200 ₽ в год у любого регистратора),
  создайте у него запись типа A с IP сервера и впишите домен в `DOMAIN`.
- **Смотреть, что происходит:** `docker compose logs -f api` (выйти: `Ctrl+C`).
