# Как выложить сервер BeerVia в интернет

После этого приложение работает с любого телефона, а ваш компьютер для сервера больше не нужен.
Мы используем **Render**: он сам берёт код с GitHub, собирает сервер, поднимает базу PostgreSQL
и обновляет сервер, когда в ветку приходят изменения.

> Всё описанное ниже проверено на уровне кода: сервер собирается, применяет миграции на пустой
> Postgres, сам загружает каталог пива и запускается. Сам конфиг Render (`render.yaml`) написан по
> документации из памяти и в Render не запускался. Если Render на каком-то шаге предложит другое
> название тарифа или поля, выбирайте ближайшее по смыслу: суть не меняется.

## Что понадобится

- Аккаунт на [render.com](https://render.com) (можно войти через GitHub) и банковская карта.
  **Проверьте заранее, что Render открывается и принимает вашу карту из вашей страны.**
- Репозиторий `MorningDawning/first-project` на GitHub (он уже есть).

Примерная стоимость (уточните на странице тарифов Render, цены меняются): сервер около 7 $/мес,
база Postgres около 6 $/мес, диск для фото и голосовых 2 ГБ меньше 1 $/мес.

## Шаг 1. Создать сервер и базу

1. На render.com нажмите **New +** → **Blueprint**.
2. Подключите GitHub и выберите репозиторий `first-project`.
3. В поле **Branch** укажите ветку, из которой брать код. Сейчас это `claude/app-development-og0ydh`.
4. Render прочитает файл `render.yaml` из репозитория и покажет, что создаст: сервис `beervia-api`
   и базу `beervia-db`. Проверьте тарифы и нажмите **Apply**.
5. Подождите 5–10 минут, пока идёт сборка. Успех выглядит так: у сервиса `beervia-api` статус
   **Live**, а в логах есть строки «Каталог пива загружен ✅» и «BeerVia API listening».

Секретный ключ для входа (`JWT_SECRET`) Render придумает сам. Ничего вручную вводить не нужно.

## Шаг 2. Проверить, что сервер отвечает

Откройте страницу сервиса `beervia-api`, вверху будет адрес вида
`https://beervia-api-xxxx.onrender.com`. Откройте в браузере этот адрес плюс `/health`, то есть
`https://beervia-api-xxxx.onrender.com/health`. Должно появиться `{"ok":true}`.

## Шаг 3. Подключить приложение к серверу

В папке `D:\beervia-app\mobile` создайте файл `.env` (можно скопировать `.env.example`) и впишите
свой адрес, без `/health` и без слэша в конце:

```
EXPO_PUBLIC_API_URL=https://beervia-api-xxxx.onrender.com
```

Затем перезапустите приложение с очисткой кэша:

```
cd /d/beervia-app/mobile
npx expo start --clear
```

Дальше приложение ходит на сервер в интернете. Комп для сервера включать не нужно.
Чтобы вернуться к серверу на своём компьютере, удалите строку из `.env`.

## Шаг 4. Первый аккаунт

База на сервере **пустая**: там есть только каталог пива. Старые аккаунты и переписка с вашего
компьютера не переносятся (это были тестовые данные). Зарегистрируйтесь в приложении заново.

Чтобы у вашего аккаунта появились вымышленные друзья, посты и переписка (для показа), на своём
компьютере в папке `server` выполните (адрес базы возьмите в Render: база `beervia-db` →
**Connections** → **External Database URL**):

```
DATABASE_URL="скопированный-адрес" npm run seed:social
```

Эта команда только добавляет данные и ничего не стирает.

> **Никогда не запускайте `npm run seed` на облачной базе.** Он стирает всё. Скрипт сам откажется
> работать не на локальной базе, но лучше об этом помнить.

## Как обновлять сервер

Когда новый код попадает в ветку, которую вы указали в шаге 1, Render сам пересобирает и
перезапускает сервер. Изменения в базе (миграции) применяются при запуске автоматически.
Во время перезапуска сервер недоступен около минуты.

## Что важно знать

- **Фото и голосовые** хранятся на постоянном диске сервера (`/data/uploads`). Пока сервер один,
  этого достаточно. Для большой аудитории позже понадобится облачное хранилище (S3 или подобное).
- **Резервные копии базы.** Проверьте в настройках базы в Render, включены ли ежедневные копии на
  вашем тарифе. Это ваши пользовательские данные.
- **Распознавание этикеток** (ML-сервис из папки `ml/`) на сервер не выкладывается. Пока
  `ML_SERVICE_URL` не задан, сканирование работает в резервном режиме, как и раньше.
- **Уведомления, когда приложение закрыто**, пока не сделаны.
- **Доступность из России.** Если телефон не достаёт до Render без VPN, сервер можно перенести
  к российскому провайдеру: файл `server/Dockerfile` работает на любом хостинге с Docker и
  Postgres, нужно задать переменные `DATABASE_URL`, `JWT_SECRET` (случайная строка от 24 символов),
  `NODE_ENV=production` и `UPLOADS_DIR`.

## Разработка на своём компьютере

Теперь база данных — Postgres, поэтому старая команда `npm run dev` без базы не заработает.
Варианты:

1. **Не запускать сервер локально** и работать с сервером в интернете (шаг 3). Самый простой путь.
2. Поднять Postgres через Docker Desktop: в папке `server` выполнить `docker compose up -d`,
   затем `cp .env.example .env`, `npx prisma migrate dev`, `npm run seed`, `npm run dev`.
